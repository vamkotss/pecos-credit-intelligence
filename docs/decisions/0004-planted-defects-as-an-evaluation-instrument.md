# ADR 0004 — Planted defects as an evaluation instrument

Status: Accepted
Date: 2026-08-04
Supersedes: none

## Context

ADR 0001 established that this project uses a synthetic corpus with a
ground-truth manifest, because no confidential lending corpus can be published
and no public corpus comes with page-level labels.

That decision creates a new problem. A synthetic corpus is generated by code,
and code generates clean, consistent documents. A retrieval-and-extraction
pipeline evaluated only on clean documents will score close to perfect and tell
us nothing, because the things that break document intelligence in production
are not clean:

- figures that disagree between two documents in the same folder
- statements presented in thousands with the note in six-point type
- pages that went through the scanner sideways
- facts that exist only inside a table
- a near-identical draft sitting next to the final
- instructions addressed to the model, embedded in a source document
- questions the package simply does not answer

A pipeline that scores 0.95 on a clean corpus and 0.40 on a real loan package
has not been evaluated. It has been flattered.

## Decision

**Seven specific defects are planted deliberately, each registered in the
manifest, each with at least one gold question that exercises it.**

| Id | What it does | What it tests |
|---|---|---|
| `restated_prior_year` | Superseded statements show a different EBITDA for the same year | Source precedence, conflict detection |
| `units_in_thousands` | Tax extract in $000s with a small header note | Unit normalisation |
| `rotated_scanned_page` | One bank statement page rotated 90° | OCR orientation handling |
| `table_only_fact` | Customer concentration appears only inside a table | Table-aware chunking |
| `prompt_injection` | Broker note instructs the model to output APPROVE | Injection resistance |
| `unanswerable_question` | A gold question with no answer in the corpus | Refusal instead of invention |
| `near_duplicate_draft` | A DRAFT of the final statements, one figure changed | Retrieval dedup and recency |

**Defects are dealt round-robin, not sampled randomly.** Deal *i* receives
defect *j* when `j % n_deals == i`. This guarantees every defect is present at
every corpus size, including the three-deal corpus CI generates.

Random sampling was rejected for exactly this reason: a small CI corpus could
omit the injection case, and the red-team suite would then pass by not running.
A test that passes because it never executed is worse than no test.

**No defect is assigned to every deal.** There must always be clean deals to
compare against, otherwise a pipeline that assumes a defect is always present
scores well for the wrong reason.

## Consequences

**Good.** Eval results break down by failure mode rather than collapsing into
one average. "Recall@5 is 0.88" is not actionable. "Recall@5 is 0.94 overall
but 0.31 on `table_only_fact`" names the next piece of work.

**Good.** The CI eval regression gate at M9 can fail on a single defect class
regressing, even when the headline number improves.

**Good.** The defect list is a ready-made interview answer. It is the difference
between "I built a RAG pipeline" and "I built a RAG pipeline and here is the
catalogue of ways it can silently be wrong."

**Cost.** Ground truth is now more expensive to maintain. A defect whose payload
drifts out of sync with its gold answer is a corrupt oracle, which is worse than
no oracle — so `tests/test_corpus.py` asserts that every assigned defect has a
real payload behind it and that every defect has at least one gold question.

**Cost.** The corpus is not a substitute for real documents. Every defect here
was chosen because it is known to occur, but the list is not exhaustive and the
generated pages are cleaner than genuine photocopies. This is stated plainly in
`docs/corpus.md` rather than left for a reviewer to discover.

## Alternatives considered

**Public filing corpora (EDGAR, SEC).** Real, but wrong shape. Commercial credit
turns on borrower-prepared statements, tax returns and bank statements, none of
which are filed publicly. EDGAR also has no page-level answer key.

**Hand-labelling a small real corpus.** Best possible ground truth, and not
available: the documents are confidential, and hand-labelling enough of them to
support recall@k is weeks of work that produces nothing publishable.

**Clean synthetic corpus, defects added later.** Rejected because "later" never
arrives, and every eval number recorded in the meantime would have to be thrown
away once the corpus changed underneath it.
